# Iteration 3 値と行き詰まり

Iteration 3で扱う意味論の考え方を説明する．
例には，自然数と真偽値を持つ小さな言語の式を使う．

## 値の種類が増える

言語に真偽値を足すと，評価の結果は自然数か真偽値のどちらかになる．
評価の結果として認める式を，値という．
値の集合を，構文とは別に定める．

```math
v ::= n \mid \mathrm{true} \mid \mathrm{false}
```

規則は，部分式の値がどの種類かを前提に書く．
足し算の規則は，両辺の値が数のときだけ使える．
`if`の規則は，条件の値が真偽値のときだけ使える．

## 行き詰まった式

$1 + \mathsf{true}$には，どの規則も当てはまらない．
小ステップ意味論では，この式はそれ以上簡約できないが，値でもない．
このような式を，行き詰まった式という．

```math
\mathit{Stuck}(t) \iff t \text{は正規形} \land t \text{は値でない}
```

行き詰まった式は，実際の処理系では実行時エラーにあたる．
大ステップ意味論では，行き詰まる式には値がない．
評価器は，値がないことを`none`で表す．

行き詰まりは，式の途中に現れることもある．
$(1 + 2) * \mathsf{iszero}\ 0$は，2ステップ簡約すると$3 * \mathsf{true}$になって行き詰まる．

## 評価器が値を返さない場合

評価器は，すべての式に値を返すとは限らなくなった．
このとき，健全性と完全性の両方が必要になる．

- 健全性だけでは，「どの式にも`none`を返す評価器」も条件を満たしてしまう．
- 完全性は，値のある式には評価器が必ずその値を返すことを保証する．

## 評価戦略は設計の選択である

`if`では，条件を先に評価し，その値によって一方の枝だけを評価する．
選ばれない枝は評価しないので，$\mathsf{if}\ \mathsf{true}\ \mathsf{then}\ 1\ \mathsf{else}\ (1 + \mathsf{true})$の値は$1$である．

`then`の枝を条件より先に簡約してもよい，という規則を足した言語を考える．

```math
\frac{t \longrightarrow t'}{\mathsf{if}\ c\ \mathsf{then}\ t\ \mathsf{else}\ e \longrightarrow \mathsf{if}\ c\ \mathsf{then}\ t'\ \mathsf{else}\ e}
```

すると$\mathsf{if}\ \mathsf{true}\ \mathsf{then}\ 1 + 2\ \mathsf{else}\ 0$は，次の2通りに簡約できる．

- 条件で枝を選ぶ：$1 + 2$．
- `then`の枝を先に簡約する：$\mathsf{if}\ \mathsf{true}\ \mathsf{then}\ 3\ \mathsf{else}\ 0$．

規則を1つ足しただけで，決定性が成り立たなくなる．
この例ではどちらの道を通っても最後は$3$になる．
しかし，評価に時間のかかる枝や評価の終わらない枝があると，結果が変わる．
Iteration 7で，評価が終わらない式を扱う．

## 機能を足すと，成り立っていた性質が崩れることがある

Iteration 0では，どの式$t$についても$t * 1$と$t$は等価だった．
真偽値を足すと，$\mathsf{true} * 1$は行き詰まるが，$\mathsf{true}$の値は$\mathrm{true}$である．
この等価性は「$t$の値が数なら」という条件付きでしか成り立たない．

言語に機能を足すときは，既存の性質を1つずつ確かめ直す．
定理として書いておけば，崩れた性質はLeanが証明の失敗として知らせる．
