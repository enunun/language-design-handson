# Iteration 2 簡約列の表示

このIterationでは，式を1ステップずつ簡約する小ステップ意味論を定め，コマンド`mini steps`で簡約の過程を表示する．
小ステップ意味論が決定的であることと，Iteration 1の大ステップ意味論と同じ意味を与えることを証明する．

## 2-1 準備

このパッケージは，Iteration 1の解答と同じ状態から始まる．

``` sh
cd iterations/iteration-2/exercise
lake build
lake test
```

Iteration 1までのテストがすべて通ることを確かめる．

## 2-2 構文と概念

次の2つのノートを読む．

- [帰納法の一般化と`Option`](../../../docs/lean/iteration-2.md)
- [小ステップ意味論](../../../docs/semantics/iteration-2.md)

読み終えたら，`Scratch.lean`で次の課題を試す．

1. ノートの`sumOf_unique_bad`を書き写し，Infoviewで`cons`の場合の`ih`を確かめる．`generalizing s₂`を足して証明を通す．
2. `#eval ([] : List Nat).head?.map (· + 1)`の結果を予想してから確かめる．
3. `∃ n, n + 2 = 5`を`⟨_, _⟩`で証明する．

## 2-3 テストリスト

### 要件

- 式を1ステップずつ簡約し，最初の式から結果までの列を表示する．
- 簡約は左の部分式から順に行う．

### 使用例

```text
$ lake exe mini steps "(1 + 2) * (3 + 4)"
(1 + 2) * (3 + 4)
⟶ 3 * (3 + 4)
⟶ 3 * 7
⟶ 21
```

### 作るもの

| モジュール | 定義 | 内容 |
| --- | --- | --- |
| `Mini.SmallStep`(新規) | `inductive Step : Term → Term → Prop`(記法`t ⟶ t'`) | 小ステップ意味論 |
| | `inductive Steps : Term → Term → Prop`(記法`t ⟶* t'`) | 0ステップ以上の簡約．構成子は`refl`と`step` |
| `Mini.Eval` | `def step : Term → Option Term` | 1ステップ簡約した式．簡約できないときは`none` |
| `Mini.Pretty`(新規) | `def Term.pretty : Term → String` | 式を具体構文の文字列にする．必要なところだけかっこを付ける |
| `Mini.Run` | `def runSteps : String → String` | 簡約列を1行に1つずつ表示する文字列．2行目からは先頭に`⟶`と空白を付ける |
| `Main` | コマンド`mini steps <式>` | `runSteps`の結果を表示する |

### 課題

確かめるべきことを`TESTLIST.md`に書き出す．

- 簡約の具体例を考える．次の3点を確かめる．
  - 左の部分式から簡約する．
  - 左が数になったら，右を簡約する．
  - 左が数になるまでは，右を簡約しない．
- 小ステップ意味論の性質を考える．数は簡約できるか．1ステップで簡約した結果は1つに決まるか．大ステップ意味論とはどう関係するか．
- `step`と`Step`の関係を，Iteration 1の`eval`と`Eval`の関係にならって考える．
- `Term.pretty`がかっこを付ける場合と付けない場合の具体例を考える．
- `runSteps`の具体例を，文字列の入力で考える．数だけの式と構文エラーも入れる．

## 2-4 設計書

- `design/spec.md`
  - `## 意味`：小ステップ意味論`Step`の規則と，多ステップ簡約`Steps`の規則を足す．演算子ごとに，左を簡約する規則，右を簡約する規則，計算する規則の3つがある．
  - `## 性質`：テストリストの性質を足す．
- `design/modules.md`：新しいモジュール`Mini.SmallStep`と`Mini.Pretty`を足す．どのモジュールが`Mini.Pretty`を使うかを考える．

## 2-5 テストファーストの実装

### `Mini.SmallStep`

1. `Mini/SmallStep.lean`を作ってライブラリに登録し，`MiniTest/Unit/SmallStepTest.lean`を作ってテストに登録する．
2. 簡約の具体例を1つずつ足しながら，`Step`に規則を足していく．
3. 性質のテストを書き，証明する．

次のヒントを参考にする．

- 規則`addR`の左の部分式は`.num n₁`の形にする．こうすると，左が数になるまで右を簡約しない．
- 決定性は，`h₁`についての帰納法を`t₂`を一般化して行い，各場合で`h₂`を`cases`で分解する．ありえない組み合わせは，`cases`で前提の導出を分解すると消える．
- 大ステップ意味論との一致には，多ステップ簡約についての補題が要る．`Steps`の推移性と，部分式の簡約列を式全体の簡約列にする補題(`add t₁ t₂ ⟶* add t₁' t₂`など)を先に証明する．
- 左向き($t \longrightarrow^{*} n$から$t \Downarrow n$)は，「1ステップ簡約した式の値は，簡約する前の式の値でもある」という補題を先に示す．`Steps`についての帰納法では，`generalize`で`Term.num n`を変数にする．

### `step`

`MiniTest/Unit/EvalTest.lean`に，`step`の具体例と性質を足してから，`Mini/Eval.lean`に`step`を実装する．

次のヒントを参考にする．

- `step`は，演算子ごとに`match t₁, t₂ with`で場合を分ける．両方が数なら計算し，左だけが数なら右を，それ以外なら左を簡約する．
- 部分式の簡約結果を式全体に戻すには`Option.map`を使う．
- 健全性の証明では，`unfold step at h`で定義を展開してから`split at h`で場合を分ける．
- 完全性の証明では，`addL`などの場合に前提の導出を`cases`で分解する．すると左の部分式の形が決まり，`step`を計算できるようになる．

### `Term.pretty`

`MiniTest/Unit/PrettyTest.lean`を作り，具体例を足してから`Mini/Pretty.lean`を実装する．

次のヒントを参考にする．

- 「その式を置く位置の結合の強さ」を引数に持つ補助関数を作る．置く位置より弱い演算子の式には，かっこを付ける．
- 左結合なので，右の部分式は1つ強い位置に置く．
- 文字列を返す関数の具体例は，`decide +kernel`で証明する．

### `runSteps`と`mini steps`

統合テストを足してから，`runSteps`と`Main.lean`のコマンドを実装する．

次のヒントを参考にする．

- `step`を繰り返して式の列を作る関数を，繰り返しの上限(燃料)を引数にとる形で書く．演算子の数だけ簡約すれば数になるので，上限には式の演算子の数を使える．
- 文字列のリストは`"\n".intercalate`でつなげる．

最後に，`lake exe mini steps "(1 + 2) * (3 + 4)"`が使用例のとおりに表示することを確かめる．

## 2-6 振り返り

1. 自分の`TESTLIST.md`を，`solution/TESTLIST.md`と比べる．
2. 小ステップ意味論の決定性は，規則のどの書き方で保証されているか．`addR`の左の部分式を`.num n₁`ではなく任意の式にすると，決定性はどうなるか．
3. 大ステップ意味論と小ステップ意味論が一致することを証明した．`eval`と`step`のそれぞれについて健全性と完全性を示した．これらを合わせると，何と何が一致すると言えるか．
4. 設計書と実装を見比べ，`mise run check-design`で`一致`になるまで設計書を直す．

## 2-7 発展課題

右の部分式から先に簡約する小ステップ意味論`StepR`を定義する．
`StepR`についても，決定性と，大ステップ意味論との一致が成り立つかを確かめる．
結果が成り立つ理由，または成り立たない理由を，言語仕様書の`## 性質`に書く．

これも，テストリスト，設計書，実装の順に進める．
